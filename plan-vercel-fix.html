Problem

https://html-planner-server.vercel.app returned 404: NOT_FOUND from Vercel's infrastructure. The build status showed "success" but the Python function was never deployed — no routes, no function invocations, just a Vercel error page.

Root Causes (5 compounding issues)

CRITICAL 1. Legacy builds config + wrong entry point

vercel.json used the legacy builds array with "src": "backend/main.py". Modern Vercel (v48+) ignores project settings when builds is present, and the @vercel/python runtime couldn't find the function at a non-standard path.

CRITICAL 2. requirements.txt only in backend/

@vercel/python looks for requirements.txt at the project root, not relative to the entry point. With the file buried in backend/, no dependencies were installed during the build.

CRITICAL 3. pyproject.toml + requirements.txt conflict

Both files existed in backend/. Vercel 48.2.0+ prefers pyproject.toml + uv when both are present. Without a uv.lock, the build silently skipped dependency installation. The .vercelignore in backend/ was ignored — Vercel only reads it at the project root.

MODERATE 4. Broken imports in source code

  • routes/page.py:7 — from models import Plan referenced a non-existent models module. Fixed to from db import Plan.
  • main.py:50 — app.add_middleware(EnsureDBInitMiddleware) referenced an undefined class. Removed (the RegisterTortoise lifespan already handles DB init).
  • tortoise_conf.py:41 — "models": ["db", "aerich.models"] still referenced aerich after it was removed from dependencies. Crashed on cold start.

MODERATE 5. .python-version set to 3.14

Vercel doesn't support Python 3.14. Fixed to 3.12.

Key Takeaway

Vercel Python conventions are opinionated:

  • Functions go in api/ (auto-detected) — not in arbitrary subdirectories
  • requirements.txt goes at the project root — not next to the entry point
  • Don't mix pyproject.toml + requirements.txt without a lockfile — Vercel prefers uv and silently fails
  • .vercelignore must be at the root — copies in subdirectories are ignored
  • builds is legacy — use functions+rewrites
