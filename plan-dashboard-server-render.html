Server-Side Dashboard Rendering Plan

Convert the dashboard from client-side JS API calls to server-side Jinja2 template rendering, optimize queries, add per-plan archive, and switch version control to jj.

Goal

Eliminate all client-side JavaScript fetch() API calls from the dashboard page. Instead, pass data from the backend directly into the Jinja2 template for server-side rendering. This makes the dashboard faster (no client-side data hydration), works without JavaScript, and enables better SEO and accessibility.

Phases

Phase 1: Database — Add is_archived to Plan model

  • Add is_archived = fields.BooleanField(default=False) to Plan in db.py
  • Create migrations/0003_plan_archive.py
  • Apply migration to Turso Cloud database

Phase 2: Backend — Server-side data passing & form-based actions

  • Modify /dashboard endpoint to fetch all data server-side and pass it to the template
  • Replace JSON responses for archive/pin/unpin/unarchive with redirects back to dashboard
  • Add POST /api/plans/{id}/archive and POST /api/plans/{id}/unarchive endpoints
  • Optimize queries with prefetch_related or select_related where needed

Phase 3: Frontend — Server-side Jinja2 template rendering

  • Replace all JavaScript fetch() calls with server-rendered HTML
  • Use Jinja2 {% for %} loops for plans and projects
  • Use <form> with POST buttons for archive/pin/unpin/unarchive actions
  • Keep CSS styles; remove JS-only styling logic
  • Remove all JS functions: loadPlans, renderPlans, delPlan, approvePlan, etc.

Phase 4: Version Control — Switch to jj

  • Create .jjignore file (replaces .gitignore)
  • Remove .gitignore or keep it for git compat
  • Verify jj is configured as primary VCS
